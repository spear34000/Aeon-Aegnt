## What the sources say

- **Mem0.** When a message pair arrives, a model extracts *candidate* memories from it, given a running summary, the last 10
  messages and the new pair. Each candidate is compared with the 10 most similar kept memories and the model picks ADD, UPDATE,
  DELETE or NOOP. Reported (LOCOMO): Mem0 66.88 overall J, 1,764 retrieval tokens, 1.440 s p95 latency; full context 72.90, 26,031
  tokens, 17.117 s. So the gain is latency and tokens; **accuracy was higher with the full context.** Mem0g (graph) 68.44.
- **Zep.** Facts are edges with four times: when they were added and retired in the system, and when they were true and stopped
  being true. A contradicting fact does not delete the old one; the old edge is marked no longer valid, which keeps the history.
  Search combines embeddings, Okapi BM25 and graph search, then reranks (reciprocal rank fusion, maximal marginal relevance,
  cross-encoders). Reported: LongMemEval 63.8 vs 55.4 for the full context (gpt-4o-mini), latency 3.20 s vs 31.3 s.
- **CoALA.** Working memory, and long-term episodic (past experience), semantic (knowledge) and procedural (code, prompts)
  memory. Retrieval is a read, learning is a write; writing to procedural memory is called significantly riskier; deletion and
  editing are described as understudied; learning can be deferred to the end of an episode and summarised first.
- **LangMem.** Semantic memory as a collection of records or a profile that is updated in place; episodic memory as examples of
  past successes; procedural as instructions refined by feedback. Memories can be formed "on the hot path" (in the
  conversation, adds latency) or in the background after it. Over-extraction costs precision, under-extraction costs recall.
- **Anthropic memory tool.** The model looks at its memory first and reads it back on demand; the application owns the storage
  and must validate paths, cap sizes, expire what is not used and keep sensitive information out.
- **A-MEM (abstract).** Notes with keywords and tags that are linked to related notes; new notes can update old ones.
- **MemoryBank (abstract).** The Ebbinghaus forgetting curve inspires weakening and reinforcing memories by time and
  significance. **The abstract gives no formula.**
- **Survey (abstract).** Memory as token-level, parametric or latent; factual, experiential and working; formation, evolution
  and retrieval. Trustworthiness is listed as an open problem.

## What Aeon does (`src/node/memory.ts`, `memory-tools.ts`)

| Idea | In Aeon | Not done |
|---|---|---|
| Candidates, compared before adding (Mem0) | At the end of a task the agent may add `remember` (at most 2). After the task is really done, each is compared with what is kept by character similarity (no embeddings): the same is dropped, a close one (50% to 85% alike) is offered as a correction of that memory | A model deciding ADD/UPDATE/DELETE/NOOP (it would cost a call and could invent); contradiction detection (rules cannot see it) |
| Formed outside the task (LangMem background) | Suggestions wait in the memory page ("제안") and are not used by any task until the owner accepts, optionally in their own words | A background pass over whole conversations |
| Do not overwrite silently (Zep) | A changed memory keeps its older wordings as history (three); an end date makes a memory "past" for 30 days, then it is removed. **Deleting a memory deletes its history** | A full temporal graph; two time axes |
| Hybrid retrieval and diversity (Zep) | Relevance is BM25-style over the kept memories, added to recency and importance (Generative Agents); a memory that is used fades more slowly; two memories 70% alike are not both put in a prompt | Embeddings, cross-encoders, graph search |
| Forgetting by use (MemoryBank) | Rank fades with time and is lifted by use. **The formula is Aeon's own design, not MemoryBank's.** Facts unused for 90 days are only suggested for tidying | Deleting by fading |
| Past experience (CoALA episodic) | `memory.search` also reads what finished tasks did (read only, 3 at most), and counts as private data for the "no sending out after reading private data" rule | Putting past tasks in prompts automatically; learning from them |
| Editing and deleting are part of memory (CoALA) | The owner edits, sets a period and deletes; the agent can ask to correct (`replaces`) or forget (`memory.forget`) a memory, each as an approval that shows the exact text | |
| Just-in-time retrieval, expiry, size caps (Anthropic) | `memory.search` reads on demand; 200 memories, 300 characters each; secrets refused; past and unused memories surface for the owner | |

The writes stay behind the owner: `memory.save`, `memory.forget` and accepting or editing a suggestion need the machine or an
admin device (writing to what steers every later task is the risky act the CoALA paper warns about).

## What this does not prove

That a real model proposes useful suggestions, that character similarity finds the right "close" memory in Korean and English
alike, or that the ranking suits real use. A suggestion inbox the owner never reads is a memory that never grows; one the owner
accepts without reading is a path for text from a web page into every later task (the suggestions are limited, filtered for
secrets, addresses and instruction-like text, and shown with the task they came from, but the filter is a heuristic).
