| D20 | Skills from outside, in two scopes, with scripts. | D21 | Skill scripts on the computer itself. D7 said commands run only in the Docker sandbox. The owner (2026-11-13, "ㅇㅇ ㄱㄱ" to the question whether to reverse D7 for this) allowed running skill scripts directly on the computer, with approval every time and restricted execution. | **D7 is reversed only for `skill.run`, and only when a task asks for `isolation: "host"`; there is still no general host-command tool, and Docker stays the default.** Per run: the owner reads the whole script and an isolation sentence on the approval card; the script runs from a fresh copy of the bytes the lock file approved, in a fresh scratch folder that is deleted afterwards; the environment is emptied (no keys or variables of the owner; only PATH and a scratch HOME/TEMP); no shell; 60 s limit; output capped at 200 KB; arguments are single-line and shown quoted. **JavaScript** runs under Node's permission model, configured so it reads only the skill copy and the scratch folder, writes only the scratch folder and starts no programs (Node 20 or later). **That is a safety net against mistakes, not a boundary against hostile code, as Node itself says; symlink bypasses were fixed in later Node releases and the exact fixed version was not checked; the network is not blocked**. **Python and shell scripts have no isolation** besides the limits above and the card says so ("Isolation: NONE").
